# Interview bank: восстановление после удаления

## Причина и исправление

`materials` и `folders` удаляются мягко, а `interview_question_profiles`
сохраняет `material_id` и уникальный `(owner_id, seed_key)`. Старый импорт
находил профиль, затем считал только активные материалы в активной папке.
Нулевой результат приводил к `Skipped++`, оставляя новую import-папку пустой.

Теперь импорт сверяет состояние каждого seed-вопроса внутри существующей
транзакции с блокировкой строки пользователя:

1. Находит профиль по **owner_id + seed_key**.
2. Читает связанный материал, включая soft-deleted запись, и состояние папки.
3. Активный неизменённый материал учитывает как `skipped` / unchanged,
   не меняя его версию профиля или время обновления.
4. При изменённых seed-метаданных обновляет существующие данные и считает `updated`.
5. Удалённый материал восстанавливает с прежним ID и привязывает к активной
   import-папке. Удалённая старая папка остаётся удалённой. Счётчик — `created`.
6. Если строки материала физически нет, создаёт её. Обычный FK удаляет профиль
   каскадно при hard delete, поэтому следующий импорт создаёт новую каноническую
   пару. Для унаследованного orphan-профиля поддерживается восстановление строки
   с известным `material_id`.

Выбрана стратегия **restore** для soft delete: сохраняются material ID,
связи истории, SRS и ручные ответы. Новые seed-ответы заполняют только пустые
поля или `.`; существующий непустой ответ/источник не перезаписывается.
Проверка владельца запрещает перенос материала другого пользователя даже при
некорректной связи профиля. Профили не удаляются для обхода уникальности.

Создание папки, восстановление материала, обновление профиля, связей и запись
import run атомарны. Одновременные импорты одного пользователя сериализованы
существующей блокировкой пользователя. Обработчик HTTP не содержит исправлений
состояния; логика остаётся в `interview.Store` и его SQL-помощниках.

Для Go соответствующий полный размер — 130. Вся коллекция содержит 368
вопросов в 15 доменах. Префикс `ALG` включает 15 вопросов, но домен

`internal/core/interview/seed/interview_questions.json` побайтно заменён файлом
`interview_questions(1).json`, имя в проекте сохранено. Все 368 кратких ответов
взяты из этого файла; ответы не генерировались. Статус вопросов остаётся `draft`,
`full_answer` и `source` остаются `.` согласно входным данным.

SHA-256 нового файла:
`f189b41e6024250fa82975f1af00870cfa772c1daa179b7f9e65801ebb00bbe3`.
Строка seed_revision во входном файле не изменилась; журнал импорта дополнительно
сохраняет SHA-256 обоих файлов. `.gitattributes` сохраняет точные байты JSON
независимо от настройки Git `core.autocrlf`.

Сопоставление полей: `short_answer → values.short_answer`,
`full_answer → values.answer`, `source → values.sources`.
Второй независимо редактируемой копии подробного ответа нет.

## Проверки

В `internal/core/training/handler/interview_reimport_test.go` добавлены настоящие
PostgreSQL/HTTP regression tests:

- Algorithms (8) и Go (130): первый импорт, неизменённый повтор, удаление папки,
  восстановление, повтор после восстановления, актуальный `GET /library`.
- Частичное удаление: одна восстановленная карточка и семь неизменённых.
- Сохранение ID, ручного ответа и полного снимка SRS.
- Активные материалы никогда не ссылаются на удалённую папку.
- Сохранение данных второго пользователя и запрет чужого DELETE.
- Изменённые метаданные действительно обновляются.
- Hard delete с каскадом и физически отсутствующий материал при legacy-профиле.
- Два конкурентных импорта после удаления не создают дубли.
- Ошибка обновления профиля откатывает материал и создание/перепривязку папки.

Тесты работают только в отдельных случайно названных схемах PostgreSQL.
Пользовательские таблицы не очищаются. Для запуска требуется
`TRAINING_TEST_DATABASE_URL`; без этой переменной интеграционные тесты явно
пропускаются. В выполненном прогоне переменная была установлена из локальной
конфигурации тестовой базы.

В `web/tests/seed-reimport.spec.ts` браузерные сценарии Algorithms/Go используют
реальный backend и новые тестовые аккаунты. Проверяются импорт, уведомление,
DELETE папки, повторный импорт, обязательный refetch `/library`, единственная
активная папка, свежий счётчик, открытие карточек и перезагрузка страницы.
Frontend обхода ошибки нет: существующий refetch работает с исправленным backend.

Результаты текущей проверки:

- `go test ./... -count=1` с PostgreSQL — успешно.
- `go build -o bin/knowledge-api.exe ./cmd/api` — успешно.
- Playwright: оба отдельных сценария Algorithms/Go — успешно.
- `go test -race ./...` с PostgreSQL — успешно, гонок не обнаружено.
- `npm --prefix web run build` — успешно.
- Полный сценарий Mock Interview (import / profile / level / draft /

- `npm test` из `web` с `E2E_BASE_URL=http://127.0.0.1:8081` — **12 passed**
  (Edge): обычные тренировки, редактор, статистика, озвучка, мобильный экран,

Все перечисленные проверки удалось запустить в этом окружении. Начальные

## Изменённые файлы и миграции

- `internal/core/interview/import.go` — восстановление и счётчики импорта.
- `internal/core/interview/reconcile.go` — чтение включая удалённые строки,
  проверка владельца и сравнение содержимого/метаданных.
- `internal/core/interview/seed/interview_questions.json` — новый файл пользователя.
- `internal/core/interview/seed/validate.go`, `seed/revision_test.go` — поддержка
  заполненных кратких ответов, проверка новой редакции.
- `internal/core/training/handler/interview_reimport_test.go` — новые regressions.
- `interview_bank_test.go`, `interview_graph_test.go` в том же каталоге —
  обновлённые ожидания unchanged и заполненных кратких ответов.
- `web/tests/seed-reimport.spec.ts`, `web/tests/interview-bank.spec.ts`,
  `web/tests/mvp.spec.ts`, `web/tests/refinement.spec.ts` — браузерные проверки,
  актуальные локаторы редактора и ожидание завершения сохранения перед reload.
- `web/src/styles.css` — стабильная высота области кнопки озвучки: исчезновение
  кнопки при перевороте больше не уменьшает карточку на 4 px.
- `.gitattributes` — сохранение байтов seed-файлов.

**Новой миграции для исправления повторного импорта не требуется.** Используются
существующие `deleted_at`, `folder_id`, `material_id` и уникальность seed_key
внутри пользователя. База проекта уже имеет миграцию 22 для Next Route из
предыдущего этапа; восстановление не меняет схему и не требует очистки данных.

Для запуска: из корня выполнить `go run ./cmd/migrate`,
`npm --prefix web run build`, `go run ./cmd/api`.
Новый seed встраивается в Go-бинарник, поэтому старый backend необходимо
перезапустить после пересборки. Проверочный экземпляр запущен на
`http://127.0.0.1:8081`.
